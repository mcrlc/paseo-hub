## Findings

1. **Clearing the flag locks the org out of its active sprite trigger.** After `clearOverride`, `OrganizationTriggerStore.save` checks the entitlement on every save, so the org cannot even send `enabled: false` for the trigger that is still active (`run.target.kind: Sprite targets are not enabled for this organization.`). The dashboard has no separate enable, disable, or delete path, so an organization that loses the flag keeps a trigger it can neither turn off nor change. Runs still fail safely at the dispatch guard for now, but once dispatch exists they would keep reaching sprites. Consider letting a save that only disables, or leaves the target unchanged, skip the entitlement check, or have revocation disable sprite triggers.
2. **`env` template values are not validated at authoring time.** `GITHUB_TOKEN: "${{ paseo.bogus.path }}"` and `"${{ unterminated"` are both accepted and stored exactly as written, while the same bad expression in `worktree.newBranch` fails with `invalid workflow expression: unsupported path paseo.bogus.path` (`02-rejections.log`, probe section). The spec (5.1) resolves these templates later, when the service is written, so an author only finds a typo once sprites can dispatch.
3. **The dispatch-guard failure is logged under the wrong operation.** The engine reports `SpriteDispatchUnsupportedError` as `ERROR: workflow.launch-expression.evaluate failed`, `failureKind: "internal"` (`06-engine-dispatch.log`), because it reuses the expression-evaluation catch. Logs and alerts will file an expected "not supported yet" outcome as an internal expression failure.
4. **The legacy bundle message does not mention sprites.** Both the compiler and the install API say `Invalid discriminator value. Expected 'daemon'` for `kind: sprite` in `.paseo/hub.yml`. Nothing tells the author that sprites are supported in trigger documents, just not in bundles.
5. **Unlimited does not include sprites (as specified).** `UNLIMITED_TEMPLATE.canUseSpriteTargets` is false. A self-hosted instance without billing stamps unlimited, so its operators need an operator override before any org can use sprite targets. This matches the PR description; it is noted because it differs from every other unlimited value.
6. **Scope notes.** In the form UI, `mergeTriggerForm` on a sprite document would return a fresh daemon YAML (`07-editor-bridge.log`), but `panel.tsx` opens yaml-only documents in YAML mode and disables the form toggle, so a user cannot reach it. Scenario 3 used the Free fallback floor (no Free plan in the catalog), which logs `billing.entitlement.free.resolve failed` by design. Scenario 4 drove `OperatorConsole` with a stub account resolver that reports an instance operator; operator authorization is already covered by `src/operator/console.integration.test.ts`.
